# Спецификация конфигурации численного решателя (TOML)

**Версия формата:** `1`  
**Статус:** проект спецификации, предназначенный для реализации парсера и валидатора  
**Назначение:** описание математической задачи, расчётной области, сетки, граничных и начальных условий, численного метода и экспорта результатов.

## 1. Общие соглашения

- Формат файла — **TOML** (например, `config.toml`); имена секций и полей чувствительны к регистру.
- Интервалы в `[domain]` содержат обе границы; для сегментов кусочной функции действуют отдельные правила из § 5.4. Во всех числовых полях должны быть конечные числа; `NaN` и бесконечности не допускаются.
- Координаты обозначаются `x` и `t`, шаги — `dx` и `dt`.
- Единицы измерения должны быть согласованы между параметрами и входными данными. Сам конфиг не выполняет конвертацию единиц.
- Пути к входным файлам и каталогу результатов разрешаются **относительно каталога `config.toml`**, а не текущей директории запуска.
- Для математических выражений используется ограниченный синтаксис, описанный в разделе 6. Выполнение произвольного Python-кода в `expression` запрещено.
- В версии 1 описана модель `wave_1d`. Архитектура допускает регистрацию других моделей и методов, но они не считаются реализованными автоматически.

## 2. Полный пример

Ниже — согласованная постановка для уравнения `u_tt = c² u_xx` на `[0, 10] × [0, 20]`:

```toml
config_version = 1

[problem]
type = "wave_1d"

[parameters]
c = 1.0
L = 10.0

[domain]
x = [0.0, 10.0]
t = [0.0, 20.0]

[grid]
dx = 0.1
dt = 0.05

[solver]
method = "explicit_central"
check_stability = true
check_compatibility = true

[boundaries.left]
type = "dirichlet"
source = "constant"
value = 0.0

[boundaries.right]
type = "neumann"
source = "constant"
value = 0.0

[initials.position]
source = "function"
expression = "sin(pi * x / (2 * L))"

[initials.velocity]
source = "constant"
value = 0.0

[output]
directory = "results"
format = "csv"
save_every = 10
fields = ["position", "velocity"]
```

Для этого примера `Nx = 101` узел по пространству и `Nt = 401` временной слой, включая концы отрезков. Число Куранта `c*dt/dx = 0.5` удовлетворяет необходимому условию устойчивости классической явной центральной схемы: `c*dt/dx ≤ 1`.

## 3. Реестр секций

| Секция TOML | Обязательна | Смысл |
|---|---|---|
| Корень файла | да | Версия формата |
| `[problem]` | да | Выбор математической модели |
| `[parameters]` | зависит от модели | Именованные параметры формул и уравнения |
| `[domain]` | да | Пространственная и временная область |
| `[grid]` | да | Шаги сетки |
| `[solver]` | да | Метод и проверки |
| `[boundaries.left]` | да для `wave_1d` | Условие на левом конце |
| `[boundaries.right]` | да для `wave_1d` | Условие на правом конце |
| `[initials.position]` | да для `wave_1d` | Начальное смещение `u(x,t0)` |
| `[initials.velocity]` | да для `wave_1d` | Начальная скорость `u_t(x,t0)` |
| `[output]` | нет | Сохранение результатов |
| `[[...segments]]` | только при `source = "piecewise"` | Отрезки кусочной функции |

## 4. Поля основных секций

### 4.1. Корень файла

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `config_version` | integer | обязательно; только `1` | Версия схемы конфигурации, **не** версия приложения. |

При неизвестной версии парсер должен выдавать ошибку, а не молча угадывать структуру.

### 4.2. `[problem]`

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `type` | string | обязательно | Идентификатор модели. В данной версии документирован `"wave_1d"`. |

Для `wave_1d` рассматривается задача

`u_tt(x,t) = c² u_xx(x,t)` с двумя граничными и двумя начальными условиями.

### 4.3. `[parameters]`

Это **словарь произвольных именованных числовых параметров**, а не таблица с фиксированным набором полей.

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `c` | float или integer | обязательно для `wave_1d` | Скорость распространения; должно выполняться `c > 0`. |
| `L` | float или integer | необязательно | Пользовательский параметр, например длина области. Не вычисляется автоматически из `[domain].x`. |
| Иные имена, например `period`, `amplitude` | float или integer | необязательно | Именованные константы, доступные в `expression`. |

Ограничения на имена: латинские буквы, цифры и `_`, первый символ — буква или `_`; нельзя использовать `x`, `t`, `pi`, `e`, имена разрешённых функций. Параметры не должны ссылаться друг на друга через строки: их значения — числа.

### 4.4. `[domain]`

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `x` | массив из 2 чисел | обязательно | Пространственный интервал `[x_min, x_max]`; `x_max > x_min`. |
| `t` | массив из 2 чисел | обязательно | Временной интервал `[t_0, t_end]`; `t_end > t_0`. |

Пример: `x = [0.0, 10.0]`, `t = [0.0, 20.0]`.

### 4.5. `[grid]`

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `dx` | float или integer | обязательно | Пространственный шаг, строго положительный. |
| `dt` | float или integer | обязательно | Шаг по времени, строго положительный. |

Число узлов и слоёв вычисляется как:

- `Nx = round((x_max - x_min) / dx) + 1`;
- `Nt = round((t_end - t_0) / dt) + 1`.

До округления валидатор проверяет, что отношения `(x_max - x_min)/dx` и `(t_end - t_0)/dt` близки к целым в пределах заданной числовой погрешности. Иначе — ошибка: автоматически изменять `dx`, `dt` или концы интервалов нельзя.

### 4.6. `[solver]`

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `method` | string | обязательно | Идентификатор зарегистрированного численного метода; в примере `"explicit_central"`. |
| `check_stability` | boolean | необязательно; `true` | Проверять известные ограничения метода на шаги и параметры. |
| `check_compatibility` | boolean | необязательно; `true` | Проверять совместимость начальных и граничных условий при `t=t_0`, если такая проверка реализована. |

Для `wave_1d` + `explicit_central` проверяется `r = c*dt/dx ≤ 1`. Указанная проверка — необходимое условие для классической схемы, а не универсальное доказательство устойчивости любого метода или реализации граничных условий.

### 4.7. `[boundaries.left]` и `[boundaries.right]`

Обе секции имеют **одинаковую структуру**.

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `type` | string | обязательно | Тип условия: `"dirichlet"`, `"neumann"` или `"newton"`. |
| `alpha` | number | обязательно только для `newton` | Постоянный конечный коэффициент при значении `u`. |
| `beta` | number | обязательно только для `newton` | Постоянный конечный коэффициент при производной по внешней нормали; `beta != 0`. |
| `source` | string | обязательно | Способ задания правой части: `constant`, `function`, `table`, `piecewise` или `plugin`. |
| `value` | number | только для `constant` | Постоянное значение. |
| `expression` | string | только для `function` | Выражение, вычисляемое на границе как функция времени. |
| `path`, `interpolation`, `t_column`, `value_column` и др. | разные | только для `table` | Поля табличного источника, см. раздел 5. |
| `segments` | массив таблиц | только для `piecewise` | Части функции, см. раздел 5. |
| `module`, `function` | string | только для `plugin` | Доверенный пользовательский код, см. раздел 5. |

Условие Дирихле задаёт `u(x_boundary, t) = g(t)`; условие Неймана — `u_x(x_boundary, t) = g(t)`. **В версии 1 Нейман означает именно производную по возрастающей координате `x`**, а не производную по внешней нормали и не поток `-k u_x`. При необходимости иной конвенции следует добавить новый тип условия, а не менять знак неявно.

Для границ естественная переменная функции — `t`; `x` при вычислении всегда фиксирован соответствующим концом области.

Условие Ньютона (`newton`, условие Робина) задаётся в общей форме:

`alpha * u(x_boundary, t) + beta * ∂u/∂n(x_boundary, t) = g(t)`.

Здесь `n` — **внешняя нормаль**. Поэтому на левой границе формула имеет вид `alpha * u - beta * u_x = g(t)`, на правой — `alpha * u + beta * u_x = g(t)`. Эта конвенция относится к `newton`; для `neumann` сохраняется производная по возрастающей координате `x`.

Оба коэффициента задаются явно и не зависят от времени. `alpha` может быть нулём, `beta` — нет; для задания самого значения `u` используется `dirichlet`. Поля `alpha` и `beta` запрещены у других типов границ и у начальных условий. Их единицы должны обеспечивать согласованность слагаемых и правой части.

Правая часть `g(t)` задаётся любым из пяти источников `source`. Для закона теплообмена `-k * ∂u/∂n = h * (u - u_ext)` соответствие такое: `alpha = h`, `beta = k`, `g(t) = h * u_ext(t)`. Источник задаёт уже всю правую часть, а не только температуру среды.

Например, при `h = 2`, `k = 0.5` и постоянном `u_ext = 10`:

```toml
[boundaries.right]
type = "newton"
alpha = 2.0
beta = 0.5
source = "constant"
value = 20.0
```

Это самостоятельный пример граничной секции; начальные данные должны быть согласованы с ним. Наличие типа в конфигурации не означает его поддержку каждым численным методом: неподдерживаемое условие должно приводить к ошибке.

### 4.8. `[initials.position]` и `[initials.velocity]`

Обе секции имеют тот же интерфейс источника данных, но **не содержат поля `type`**.

| Секция | Физический смысл | Естественная переменная |
|---|---|---|
| `[initials.position]` | `u(x, t_0) = f(x)` | `x` |
| `[initials.velocity]` | `u_t(x, t_0) = v(x)` | `x` |

Для каждой секции обязательное поле `source`, а остальные поля определяются его значением (раздел 5). При вычислении начальных данных время фиксировано: `t=t_0`.

### 4.9. `[output]`

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `directory` | string | необязательно; `"results"` | Каталог вывода; создаётся при необходимости. |
| `format` | string | необязательно; `"csv"` | Формат выгрузки; для версии 1 определён `"csv"`. |
| `save_every` | integer | необязательно; `1` | Сохранять каждый `N`-й временной слой; `N ≥ 1`. |
| `fields` | массив строк | необязательно; `["position"]` | Поля результата. Для `wave_1d` определены `"position"` и `"velocity"`. |

Для `csv` предлагается один файл `directory/solution.csv` в *длинном формате*: `t,x,position,velocity` (столбцы включаются только для выбранных `fields`, но `t` и `x` присутствуют всегда). Нулевой и конечный временные слои сохраняются независимо от `save_every`. Сохранение скорости предполагает, что решатель вычисляет или реконструирует `u_t`; при отсутствии такой возможности он должен выдать ошибку, а не подменять её смещением.

## 5. Унифицированные источники данных (`source`)

Эти правила действуют во всех секциях `[boundaries.*]` и `[initials.*]`. У каждой такой секции — **ровно один** источник. Поля, не относящиеся к выбранному `source`, запрещены (кроме `type` у границ и обязательных `alpha`, `beta` у границ с `type = "newton"`). Коэффициенты условия Ньютона не являются полями источника и разрешены при любом `source`.

### 5.1. `source = "constant"`

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `value` | number | обязательно | Константное значение. |

```toml
[initials.velocity]
source = "constant"
value = 0.0
```

### 5.2. `source = "function"`

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `expression` | string | обязательно, непустое | Аналитическое выражение. |

```toml
[boundaries.left]
type = "dirichlet"
source = "function"
expression = "sin(2 * pi * t / period)"
```

Здесь `period` должен быть определён в `[parameters]`, а `x` на границе, если используется, равно фиксированной координате этой границы.

### 5.3. `source = "table"`

Табличный источник версии 1 читает CSV с заголовком. Содержимое — набор пар «аргумент, значение».

| Поле | Тип | Обязательность / умолчание | Описание |
|---|---|---|---|
| `path` | string | обязательно | Путь к CSV-файлу. |
| `interpolation` | string | необязательно; `"linear"` | `"nearest"`, `"linear"` или `"cubic"`. Для `cubic` требуется не менее 4 точек и соответствующая реализация интерполятора. |
| `x_column` | string | обязательно для начальных условий | Название колонки пространственного аргумента. |
| `t_column` | string | обязательно для граничных условий | Название колонки временного аргумента. |
| `value_column` | string | обязательно | Название колонки значений. |
| `delimiter` | string | необязательно; `","` | Разделитель CSV; один символ. |
| `extrapolation` | string | необязательно; `"error"` | `"error"` — ошибка за пределами данных; `"clamp"` — крайнее известное значение. |

`x_column` и `t_column` взаимоисключающие: в начальных условиях указывается `x_column`, в граничных — `t_column`. Столбец аргумента должен содержать строго возрастающие уникальные числовые значения; пропуски, нечисловые и бесконечные значения запрещены. Входной диапазон должен покрывать точки, в которых источник реально вычисляется, либо разрешать указанную экстраполяцию.

```toml
[initials.velocity]
source = "table"
path = "data/velocity.csv"
interpolation = "linear"
x_column = "x"
value_column = "velocity"
extrapolation = "error"
```

Пример `data/velocity.csv`:

```csv
x,velocity
0.0,0.0
5.0,0.0
10.0,0.0
```

### 5.4. `source = "piecewise"`

Кусочно-заданная функция представляет собой массив вложенных таблиц `[[<section>.segments]]`.

| Поле сегмента | Тип | Обязательность | Описание |
|---|---|---|---|
| `interval` | массив из 2 чисел | обязательно | Интервал действия сегмента `[a,b]`, `b > a`. |
| `value` | number | ровно одно из `value`, `expression` | Константа на сегменте. |
| `expression` | string | ровно одно из `value`, `expression` | Формула на сегменте. |

```toml
[initials.position]
source = "piecewise"

[[initials.position.segments]]
interval = [0.0, 5.0]
expression = "x / 5"

[[initials.position.segments]]
interval = [5.0, 10.0]
expression = "(10 - x) / 5"
```

Сегменты должны быть отсортированы, не иметь перекрытия внутренностей и полностью покрывать диапазон аргумента, на котором функция вызывается. Общая точка соседних сегментов принадлежит **правому** сегменту (полуинтервалы `[a,b)`, последний сегмент закрыт справа). Значения на общей точке могут не совпадать: разрешён разрыв, если математическая задача и метод его допускают.

### 5.5. `source = "plugin"`

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `module` | string | обязательно | Импортируемое имя Python-модуля, доступного приложению. |
| `function` | string | обязательно | Имя вызываемой функции в модуле. |

```toml
[initials.position]
source = "plugin"
module = "my_problem.initial_data"
function = "initial_displacement"
```

Предлагаемый контракт для Python-функции: `f(x: float, t: float, parameters: Mapping[str, float]) -> float`. Для начальных условий вызывается с `t=t_0`, для граничных — с `x=x_min` или `x=x_max`. Плагины исполняют **реальный пользовательский код**; их нельзя загружать из недоверенных конфигов. Безопасное вычисление `expression` не делает плагины безопасными.

## 6. Язык математических выражений

**Разрешены:** числовые литералы; переменные `x`, `t`; имена из `[parameters]`; константы `pi`, `e`; скобки; арифметические операции `+`, `-`, `*`, `/`, `**`; функции `sin`, `cos`, `tan`, `exp`, `log`, `sqrt`, `abs`.

**Не разрешены:** произвольный Python-код, обращения к атрибутам, индексация, импорт, присваивание, циклы, генераторы, чтение файлов и вызовы функций, отсутствующих в белом списке.

Примеры:

- `"sin(2 * pi * x / L)"` — допустимо;
- `"exp(-x**2)"` — допустимо;
- `"cos(2 * PI * x^2)"` — недопустимо: нужно `pi` и `**`;
- `"sin((2 * pi / l) * x)"` — допустимо только если `l` определён в `[parameters]` (регистр имеет значение).

Области определения функций проверяются при вычислении: например, `sqrt(-1)` для вещественного решателя считается ошибкой. Выражение обязано возвращать конечное вещественное число.

## 7. Правила валидации и сообщения об ошибках

1. **Структура:** известная `config_version`; правильные имена секций; отсутствие неизвестных полей и конфликтующих источников; обязательные поля заполнены.
2. **Числа и диапазоны:** `x_max > x_min`, `t_end > t_0`, `dx > 0`, `dt > 0`, `c > 0`; корректная размерность массивов. Для `newton` обязательны конечные числовые `alpha` и `beta`, причём `beta != 0`; для остальных типов эти поля запрещены.
3. **Сетка:** длины интервалов кратны шагам в пределах допусков; узлы согласуются с краями.
4. **Источники:** файлы существуют; CSV имеет нужные колонки; аргументы отсортированы и уникальны; формулы используют разрешённые операции и определённые параметры; сегменты покрывают заданный интервал.
5. **Постановка:** типы граничных условий поддерживаются моделью и методом. Для гладкого решения на `t=t_0` должны согласовываться, в частности, `f(x_min)` с левым Дирихле и `f'(x_max)` с правым Нейманом. При наличии достаточной гладкости могут проверяться также условия на начальную скорость и производные граничных данных.
   Для `newton` проверяется `alpha * f(x_min) - beta * f'(x_min) = g(t_0)` слева и `alpha * f(x_max) + beta * f'(x_max) = g(t_0)` справа с коэффициентами соответствующей границы. При проверке начальной скорости аналогичные равенства используют `v`, `v'` и `g'(t_0)`.
6. **Устойчивость:** если `check_stability = true`, проверять критерий, зарегистрированный за выбранной парой «модель + метод». Отсутствие реализованной проверки должно давать явное предупреждение, а не отчёт об успешной проверке.
7. **Вывод:** `save_every ≥ 1`; `fields` непустой, значения уникальны и поддерживаются решателем; каталог доступен для записи.

Примеры диагностик (желаемый стиль):

```text
[grid] dt: must be > 0 (received -0.1)
[initials.velocity] source=table: missing CSV column "velocity"
[boundaries.right] type=neumann: unsupported by selected method
[boundaries.left] type=newton: beta must be nonzero (received 0.0)
[solver] explicit_central: CFL = 2.0 exceeds 1.0
```

Если пользователь отключил `check_stability` или `check_compatibility`, программа пропускает только **соответствующую математическую проверку** — синтаксис, типы, обязательные поля и доступность данных проверяются всегда.

## 8. Краткая памятка разработчику

- `TOML parser` читает файл и выдаёт дерево данных.
- `Schema validator` проверяет типы, обязательность, разрешённые ключи и комбинации полей.
- `Expression compiler` компилирует ограниченное AST-выражение без `eval` над произвольным кодом.
- `Source factory` строит единую функцию `f(x,t,parameters)` для `constant`, `function`, `table`, `piecewise`, `plugin`.
- `Problem factory` связывает модель, сетку, источники и граничные условия.
- `Solver registry` по `problem.type` и `solver.method` выбирает численный алгоритм и критерии его применимости.
- `Output writer` сохраняет выбранные поля по соглашению раздела 4.9.

**Нормативное правило:** неизвестный ключ или неизвестное значение перечислимого поля — ошибка. Не следует молча игнорировать опечатки в конфиге.

## 9. Отличия от исходного черновика

- `t = [0.0. 20.0]` исправлено на `t = [0.0, 20.0]`.
- `xStep`/`tStep` заменены на единообразные `dx`/`dt`.
- `function` в качестве названия формульного поля заменено на `expression`, а `source` явно определяет способ задания данных.
- Структура источника одинаковая для границ и начальных условий.
- Добавлены явные соглашения для `Neumann`, таблиц, кусочных функций и модулей-плагинов.
- Для `newton` определены коэффициенты `alpha`, `beta`, правая часть через `source` и знаки производной по внешней нормали.
- Разделены структурная валидация и проверки математической корректности.

## 10. Текущая реализация C++

`toml-processor.hpp` содержит структуры и интерфейс, `toml-processor.cpp` — чтение и проверку конфигурации через библиотеку `toml.hpp`. Требуется C++17.

```cpp
#include "toml-processor.hpp"

int main() {
  auto config = tomlprocessor::ConfigProcessor::parse_file("test.toml");
  double dx = config.grid.dx;
  // Передать config решателю.
}
```

При сборке нужно подключить `toml-processor.cpp`. Для уже прочитанного дерева есть `ConfigProcessor::parse(table, base_directory)`. По умолчанию `base_directory` — текущая директория; `parse_file` автоматически использует каталог файла конфигурации. Пути к CSV и каталогу вывода сохраняются в `Config` как абсолютные, без создания файлов и каталогов. Отсутствующая секция `[output]` представлена `std::nullopt`; присутствующая пустая секция получает значения по умолчанию.

Парсер проверяет обязательные и неизвестные поля, точные типы TOML (числовые поля допускают целые и вещественные числа), конечность чисел, имена параметров, интервалы, положительность шагов, кратность длин интервалов шагам, коэффициенты `newton`, поля выбранного источника, покрытие сегментами и настройки вывода. Допуск кратности — `1e-8` в числе интервалов. Поддерживаемые идентификаторы сейчас: `wave_1d` и `explicit_central`; при включённом `check_stability` проверяется `c*dt/dx <= 1`.

Ошибки схемы выбрасываются как `std::runtime_error` с именем секции и поля, синтаксические ошибки TOML — как `toml::parse_error` библиотеки `toml.hpp`.

Это этап разбора конфигурации, а не полная реализация всех проверок из раздела 7. Пока не реализованы:

- Разбор и вычисление математических выражений: сохраняется исходная непустая строка. Проверка синтаксиса формул, имён и областей определения будет добавлена с библиотекой выражений.
- Загрузка CSV, проверка его наличия, колонок и данных, интерполяция и экстраполяция.
- Импорт и вызов плагинов: сохраняются только `module` и `function`.
- Проверка совместимости начальных и граничных функций: `check_compatibility` сохраняется для последующего этапа.
- Проверка поддержки граничного условия конкретной реализацией решателя, создание каталога вывода и проверка его доступности для записи.

Успешный разбор TOML не означает прохождения этих отложенных проверок.
