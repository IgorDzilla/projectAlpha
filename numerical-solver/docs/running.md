# Запуск расчётов Эйлера в 1D

Рабочая последовательная цепочка: TOML v2 → EulerConfig → RiemannProblem1D → FiniteVolume/GodunovFlux → ExplicitEuler/ExplicitSolver → CSV. Поддержаны пять входных файлов `toro_1.toml`–`toro_5.toml` в соседнем [configs](../../configs).

## Сборка и один запуск

Из каталога `numerical-solver`:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build --target solver-cli
./build/solver-cli ../configs/toro_1.toml
```

Без дополнительных аргументов результат первого случая попадёт в `../configs/results/toro_1`. Все пути из TOML отсчитываются **от каталога TOML**, независимо от текущего рабочего каталога.

Для другого каталога результата:

```sh
./build/solver-cli ../configs/toro_1.toml --output-dir /tmp/sod-new-run
./build/solver-cli --help
```

Путь `--output-dir` отсчитывается от текущего рабочего каталога. Каталог результата должен быть новым или пустым: повторный запуск не затирает предыдущие данные. Если `[output]` отсутствует, файлы не создаются; явный `--output-dir` включает вывод всех пяти полей с сохранением каждого шага.

Все пять случаев (после уже выполненного запуска используйте новые каталоги):

```sh
for i in 1 2 3 4 5; do
  ./build/solver-cli "../configs/toro_${i}.toml" --output-dir "/tmp/toro-new-run-${i}"
done
```

## Что записывается

- `solution.csv`: столбцы `time,cell,x` и поля в порядке `output.fields`; одна строка на физическую ячейку и сохранённый момент времени. `cell` начинается с нуля, `x` — центр ячейки.
- `run.txt`: модель, метод, границы, gamma, CFL, сетка, интервалы, разрыв, входные состояния, допуски, лимиты, настройки сохранения и итоговый статус.

`density`, `momentum`, `energy` — консервативные средние по ячейке. `velocity` и `pressure` получены из среднего U; это не точные средние примитивных величин. Все числа записываются с точностью 17 значащих цифр и десятичной точкой.

Начальный и конечный слои сохраняются всегда, промежуточные — через `save_every` принятых шагов. При нулевой длительности записывается один слой. При ошибке расчёта CLI возвращает ненулевой код; уже сохранённые слои остаются, в `run.txt` отмечаются `status=failed` и последнее принятое время. Ошибка записи тоже завершает запуск ошибкой; повреждённый файл не считается успешным результатом.

## Поддержанный профиль

Текущий CLI принимает только `config_version = 2` и следующую комбинацию:

| Настройка | Значение |
| --- | --- |
| `problem.type` | `euler_1d` |
| `initials.type` | `riemann` |
| `solver.method` | `finite_volume` |
| `solver.flux` | `godunov_exact` |
| `solver.integrator` | `explicit_euler` |
| Обе границы | `transmissive` |
| `output.format` | `csv` |

`solver.cfl` должен лежать в `(0, 0.5]`. `grid.cells` — положительное целое; dx выводится из `domain.x`. Время не обязано быть кратным шагу: dt пересчитывается, последний шаг сокращается до конца интервала. Точка разрыва строго внутри области; rho и p положительны, gamma больше единицы, все числа конечны.

Необязательные настройки:

- `solver.max_steps`: максимум принятых шагов, по умолчанию 1 000 000.
- `solver.exact.pressure_rtol`, `residual_rtol`: по умолчанию `1e-10`.
- `solver.exact.max_iterations`: по умолчанию 256; входные файлы Торо задают 100.
- `solver.exact.max_bracket_expansions`: по умолчанию 128.
- `output.save_every`: по умолчанию 1; `output.fields`: все пять поддержанных полей.

Секции и параметры проверяются строго. Опечатки, неизвестные методы, смешение `grid.dx/dt` с этим профилем, повторные поля вывода и неподдержанные границы вызывают ошибку до запуска. Старый `utils/ConfigProcessor` по-прежнему читает волновой TOML v1; его код сохранён. Полный волновой расчёт, перенос, Русанов, RK4 и параллельная версия пока не подключены к CLI.

## Численный смысл

Начальные данные переводятся в U=(rho,rho*u,E). Если разрыв пересекает ячейку, смешиваются консервативные состояния пропорционально длинам частей. Внутри каждой ячейки применяется постоянная реконструкция — это схема первого порядка.

На каждой грани решается одна локальная задача Римана. Поток берётся из состояния на луче xi=0 и используется обоими соседями с противоположными знаками. На внешней грани обе стороны получают состояние ближайшей внутренней ячейки (`transmissive`); отдельные хранимые фиктивные ячейки для этого не нужны.

Перед шагом готовятся все потоки и максимальная скорость, включая граничные грани. Ограничение: `dt <= CFL*dx/max_speed`. Кэш потоков сверяется с полными значениями U и временем; тот же адрес объекта с изменёнными данными не приводит к старому потоку.

Кандидат следующего слоя проверяется до принятия. Отрицательные rho/p, вакуум в локальной задаче и несходимость дают ошибку с контекстом ячейки/грани и времени; подрезки и подмены потока нет. `transmissive` не является универсальным безотражательным условием: сравнение с задачей на бесконечной прямой корректно до прихода волн к границе.

## Проверки

```sh
cmake -S . -B build-tests -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build-tests
ctest --test-dir build-tests --output-on-failure
```

12 проверок покрывают ядро, общий Solver, модель и локальный решатель, пять случаев Торо, конечные объёмы, TOML v2/CSV, пять полных CLI-запусков и старый волновой ридер. Сквозные тесты складывают результаты в дерево своей сборки, не в каталоги исходных конфигов. Подробности — в [tests/README.md](../tests/README.md).

## Графики результатов

Для plot_toro.py нужны NumPy и Matplotlib. Из numerical-solver:

```sh
python3 ../plot_toro.py ../configs/results
```

Для одного случая или другого каталога рисунков:

```sh
python3 ../plot_toro.py ../configs/results/toro_1 --output-dir /tmp/sod-plots
```

Скрипт читает solution.csv и run.txt. По умолчанию создаёт подкаталог plots внутри переданного пути: PNG по каждому случаю, общий toro_figures.pdf, REPORT.md и toro_summary.csv с минимумами/максимумами конечного слоя. Повторный запуск перезаписывает одноимённые графики и отчёты; исходные CSV и run.txt не меняются.

Профили показывают начальные и конечные численные значения; x–t использует фактические неравномерные моменты сохранения. Диаграмма p–u показывает состояния ячеек, окрашенные по координате, а не точные волновые кривые. Эталон и ошибки относительно него не вычисляются.

Скрипт проверяет завершение расчёта, количество и времена слоёв, уникальность номеров ячеек, сетку и физическую допустимость данных. Порядок строк CSV не важен. Недостающие скорость/давление восстанавливаются из консервативных величин, если они присутствуют. Для сокращённого output.fields строятся только доступные величины; p–u пропускается без давления или скорости. Один момент времени не выдаётся за эволюцию: вместо x–t выводится пояснение.
