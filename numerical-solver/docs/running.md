# Как запустить расчёт

Все команды выполняются из корня репозитория `projectAlpha`, где находятся `configs/`, `utils/` и `numerical-solver/`. [Устройство комплекса и проект развития по части 2](architecture.md).

## 1. Собрать программу

Нужны CMake и компилятор C++17.

```sh
cmake -S numerical-solver -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target solver-cli
```

Готовая программа — `build/solver-cli`. После изменения C++-кода повтори вторую команду. После изменения TOML пересборка не нужна.

## 2. Запустить один расчёт

```sh
./build/solver-cli configs/toro_1.toml --output-dir results/sod-1
```

- `configs/toro_1.toml` — откуда брать исходные данные.
- `results/sod-1` — куда записать результат.

Папка результата должна быть новой или пустой. Для следующего запуска можно указать `results/sod-2`.

Успешный запуск заканчивается сообщением `Completed`. При ошибке программа пишет `Error` и возвращает ненулевой код завершения.

Без `--output-dir` папка берётся из TOML:

```sh
./build/solver-cli configs/toro_1.toml
```

У этого конфига результат попадёт в `configs/results/toro_1`. Путь из TOML отсчитывается **от папки самого TOML**. Путь после `--output-dir` — **от папки, где запущена команда**.

Если в TOML нет секции `[output]`, расчёт выполняется без файлов. Параметр `--output-dir` включает файловый вывод даже в таком случае.

## 3. Посмотреть результат

В папке расчёта два файла:

| Файл | Что внутри |
| --- | --- |
| `solution.csv` | По одной строке на ячейку и сохранённый момент времени |
| `run.txt` | Параметры расчёта, конечное время и статус |

Столбцы CSV:

| Столбец | Значение |
| --- | --- |
| `time` | Время |
| `cell` | Номер ячейки, начиная с нуля |
| `x` | Координата центра ячейки |
| `density` | Плотность |
| `momentum` | Плотность, умноженная на скорость |
| `energy` | Полная энергия на единицу объёма |
| `velocity` | Скорость |
| `pressure` | Давление |

Первые три столбца есть всегда. Остальные выбираются через `output.fields`.

В CSV плотность, импульс и энергия — средние по ячейке. Скорость и давление вычислены из этих средних.

В `run.txt` успешный расчёт имеет `status=complete`. После ошибки могут остаться уже записанные слои. Наличие CSV само по себе не означает, что расчёт дошёл до конца.

## 4. Построить графики

Нужны Python, NumPy и Matplotlib.

```sh
python3 plot_toro.py results/sod-1
```

Готовые файлы будут в `results/sod-1/plots/`:

- PNG с профилями и диаграммами.
- `toro_figures.pdf` — все рисунки в одном PDF.
- `REPORT.md` — короткий отчёт.
- `toro_summary.csv` — минимумы и максимумы полей в конце расчёта.

На профилях показаны начальные и конечные значения. На x–t показано изменение полей во времени. На p–u показаны давление и скорость в ячейках; цвет обозначает координату.

Точного эталона и оценки ошибки на этих графиках нет. Если в CSV недостаточно полей, скрипт построит только доступные графики. Если сохранён один момент времени, диаграммы изменения во времени не будет.

Повторное построение обновляет картинки и отчёты. Сам результат расчёта не меняется.

Если Python сообщает `No module named numpy` или `No module named matplotlib`, можно установить зависимости отдельно для проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install numpy matplotlib
.venv/bin/python plot_toro.py results/sod-1
```

## Все пять задач Торо

```sh
for i in 1 2 3 4 5; do
  ./build/solver-cli "configs/toro_${i}.toml" --output-dir "results/toro-run-1/toro_${i}" || break
done
python3 plot_toro.py results/toro-run-1
```

Для повторного расчёта замени `toro-run-1` на другое имя в обеих командах. Если один из расчётов завершился ошибкой, сначала исправь её; скрипт графиков отклоняет незавершённые расчёты.

## Точные тесты и графики по пунктам 1.3–1.4

Те же TOML задают два состояния для точного решателя. Проверка не использует
сеточную схему: 2001 точка профиля — точки отбора `sample()`, а не ячейки расчёта.

```sh
cmake -S numerical-solver -B build -DBUILD_TESTING=ON
cmake --build build --target toro-plots
```

Команда собирает тест, проверяет пять задач по таблице Торо, сохраняет данные и
запускает Python. Требуются NumPy и Matplotlib в выбранном CMake интерпретаторе.

Результаты находятся в `build/toro-results`, рисунки и отчёт — в его папке `plots`:

- `toro_report.pdf` — пять страниц таблиц и 15 рисунков;
- `REPORT.md` — таблицы и пояснения к разрывам и типам волн;
- `toro_summary.csv` — расчёт, эталон, отклонения и допуски;
- `toro_*/profiles.*`, `xt.*`, `pu.*` — рисунки в PNG и PDF.

Профили содержат ρ, u, p, e, a и s с положениями волн. На x–t показаны плотность,
ударные фронты, контакт и вееры. На p–u показаны две волновые кривые и их пересечение;
для тестов 3–5 шкала давления логарифмическая. Python читает CSV, уравнение давления не решает.

Отдельные действия без общей цели:

```sh
cmake --build build --target riemann-test
./build/riemann-test
python3 plot_toro.py build/toro-results
```

Тест принимает необязательные аргументы — папку конфигов и папку результатов.
При повторном запуске он обновляет собственные CSV; исходные TOML не меняются.

## Что менять в TOML

Начни с копии [toro_1.toml](../../configs/toro_1.toml). В нём уже есть все нужные секции.

| Поле | За что отвечает |
| --- | --- |
| `domain.x` | Левая и правая границы области |
| `domain.t` | Начальное и конечное время |
| `grid.cells` | Число ячеек: больше ячеек — подробнее сетка и дольше расчёт |
| `initials.discontinuity` | Место начального разрыва, строго внутри области |
| `initials.left` | Плотность, скорость и давление слева от разрыва |
| `initials.right` | То же справа |
| `parameters.gamma` | Параметр идеального газа, больше 1; в примерах 1.4 |
| `solver.cfl` | Управляет размером шага времени; допустимо больше 0 и не больше 0.5, в примерах 0.4 |
| `output.directory` | Папка результата |
| `output.save_every` | Через сколько шагов сохранять слой |
| `output.fields` | Какие величины записывать |

Плотность и давление должны быть положительными. Число ячеек и `save_every` — положительные целые. Начальный и конечный слои сохраняются независимо от `save_every`.

Шаг времени программа выбирает сама. Задавать `grid.dt` в этих конфигах не нужно — такое поле будет отклонено.

Сейчас поддержана только эта комбинация:

```toml
config_version = 2
# problem.type = "euler_1d"
# initials.type = "riemann"
# solver.method = "finite_volume"
# solver.flux = "godunov_exact"
# solver.integrator = "explicit_euler"
# boundaries.left.type = "transmissive"
# boundaries.right.type = "transmissive"
```

Это список значений, не полный конфиг для копирования. Настройки `solver.exact` управляют поиском решения одного разрыва; для обычного запуска оставь их как в примере. `transmissive` означает, что на границе берётся состояние ближайшей ячейки.

`solver.exact.pressure_rtol` задаёт критерий из §15.7:
`2*|p_new-p_old|/(p_new+p_old) < pressure_rtol`; по умолчанию `1e-6`.
Ньютоновский шаг с недопустимым давлением или вне ограничивающего интервала
заменяется серединой интервала. `residual_rtol` проверяет невязку, если шаг округлился до нуля.
В `run.txt` поля `riemann_iterations` и `riemann_pressure_change` относятся к исходному разрыву.

## Если не запускается

| Сообщение или ситуация | Что сделать |
| --- | --- |
| `Output directory is not empty` | Укажи новую или пустую папку результата |
| Не найден TOML | Проверь путь и текущую папку терминала |
| `unknown or inapplicable field` | Проверь название параметра; не смешивай газовый и волновой форматы |
| Ошибка версии конфига | CLI принимает газовый TOML v2. Волновой v1 читает отдельный ридер из utils |
| Ошибка плотности или давления | Проверь начальные данные. Если ошибка возникла во время расчёта, посмотри указанную ячейку/грань и время |
| `vacuum` | Этот решатель пока не поддерживает вакуум |
| Ошибка сходимости или лимита шагов | Посмотри сообщение, данные задачи и настройки `solver.exact` / `solver.max_steps` |

Справка по аргументам: `./build/solver-cli --help`.
