# Проверки

CMake и CTest запускают 12 проверок без стороннего тестового фреймворка:

| Проверка | Что подтверждает |
| --- | --- |
| core | Геометрия и поля, включая узлы |
| solver | Общий цикл, интегратор, вывод и отказ без изменения состояния |
| riemann-toro | Пять табличных случаев пользовательского локального решателя |
| riemann | Модель газа, волны, контакт, вакуум, ошибки и разные масштабы |
| finite-volume | Начальная консервативная проекция, постоянное состояние, стационарный контакт, баланс с внешними потоками, CFL, актуальность кэша и сгущение Сода |
| euler-config | TOML v2, ошибки/опечатки, пути, CSV, выбор полей, сохранение начального/конечного слоёв, запрет перезаписи, отказ по бюджету шагов |
| cli-toro-1 … cli-toro-5 | Реальные запуски solver-cli по пяти TOML; проверка каждой строки CSV, начальных данных, конечного времени, допустимости и согласованности U/velocity/pressure |
| config-reader | Прежние тесты wave_1d из utils |

Из каталога numerical-solver:

```sh
cmake -S . -B /tmp/numerical-solver-build -DBUILD_TESTING=ON
cmake --build /tmp/numerical-solver-build
ctest --test-dir /tmp/numerical-solver-build --output-on-failure
```

Проверяются геометрия в 1D/2D/3D, индексация, границы, ошибки геометрии и переполнения, доступ к полю, заполнение, независимое копирование и совместимость полей. Дополнительно проверяются количество и координаты узлов в 1D/2D/3D, включение границ, узловая индексация, переполнение числа узлов и размеры полей для всех трёх вариантов хранения. Компиляционные проверки запрещают временную сетку в поле. Для проверки доступа к памяти и неопределённого поведения к сборке можно добавить `-fsanitize=address,undefined -fno-omit-frame-pointer -g`.

`solver-test.cpp` проверяет абстрактный интерфейс Solver, передачу времени в правую часть, ограничение и сокращение шага, начальный/периодический/конечный вывод, продолжение расчёта и сохранение состояния при отказе. Отдельный узловой тест проверяет размеры State и правой части, несовместимость с ячеечными полями и обновление обоих граничных узлов через ExplicitSolver. Это проверка хранения и передачи данных, не готовая волновая схема. Тестовый writer хранит результат в памяти. Незавершённая правая часть, неверный состав полей, нечисловые значения, физически недопустимый кандидат и ошибки записи проверяются отдельно.

Дальше перечислены проверки будущих компонентов численной библиотеки и адаптера. В пользовательском [utils](../../utils/tests/toml-processor-test.cpp) уже есть самостоятельные тесты ридера. Они проверяют разбор и вычисление формул, но не решатель, чтение CSV или загрузку плагинов.

| Область | Проверяемое свойство |
| --- | --- |
| Сетка и поля | Геометрия и индексы согласованы; несовместимые размеры, размещения и фиктивные слои обнаруживаются |
| Состояние | Число компонент соответствует модели; промежуточные состояния не изменяют исходные физические данные |
| Границы | Периодическое продолжение корректно; заданные значение и градиент выполняются на грани с учётом расположения неизвестных |
| Перенос | Постоянное решение сохраняется; положительная, отрицательная и нулевая скорости обрабатываются корректно |
| Сохранение | На периодической сетке дискретный интеграл меняется только в пределах обоснованной погрешности округления |
| Теплопроводность | Затухание гладкой моды согласуется с аналитическим решением при устойчивом шаге |
| Интеграторы | Изолированная задача с известным решением подтверждает порядок по времени; стадии используют правильное время |
| Зависящие от времени границы | Значения пересчитываются для каждой стадии, а не только один раз за шаг |
| Solver | В волновом профиле сохраняются фиксированные шаг и число слоёв; для других методов укороченный последний шаг проверяется при его поддержке; недопустимый шаг и нечисловое состояние дают диагностируемый отказ |
| Газовая динамика | Согласованы преобразования переменных, физическая допустимость, баланс и выбранная эталонная задача |
| Вывод | Сохранены время, сетка, имена компонент и физические ячейки; фиктивные ячейки не попадают в обычный результат |
| Последовательные заглушки | Каждый индекс посещается ровно один раз по порядку; неподдерживаемый режим не выдаётся за работающий |

## Проверки подключения конфигурации

- Существующий ридер собирается из обоих `.cpp`, его исходные тесты запускаются с рабочим каталогом `utils`, где лежит `test.toml`.
- Адаптер различает `wave_1d` и другие модели; `explicit_central` не превращается в `ExplicitEuler`. Узловая сетка сохраняет оба конца области и отличается от сетки центров ячеек.
- Пути не зависят от каталога запуска CLI: уже разрешённые ридером пути не разрешаются повторно относительно приложения.
- Начальные данные вычисляются при `t0`, граничные — на нужном конце области и нужном времени. Слева знаки условий `neumann` и `newton` проверяются раздельно.
- `table`, `plugin` и не подключённый `piecewise` приводят к раннему отказу, даже если ридер успешно разобрал описание. После реализации выбора сегмента проверяются стыки и крайний правый конец.
- При `check_compatibility = true` подтверждается выполнение проверки либо выдаётся явный отказ, если она недоступна. `check_stability = false` сохраняет проверки типов, конечности и положительных шагов.
- Сконструированные вычислители остаются работоспособными после уничтожения временного `Config`; ошибка вычисления формулы содержит контекст задачи.
- Старт волнового шага использует и смещение, и скорость; запрошенная для CSV скорость соответствует временному слою смещения, в том числе на первом и последнем слоях.
- Проверяются выбранные поля CSV, `save_every`, обязательный начальный и конечный вывод и отсутствие файлового вывода при отсутствии секции по принятому контракту адаптера.

Успех тестов парсера не доказывает готовность `utils/test.toml` к расчёту: его табличная скорость требует отдельного загрузчика и данных.

Для сходимости использовать несколько сгущений сетки и отдельно контролировать ошибку по времени. При проверке порядка интегратора пространственная ошибка не должна определять результат. Для разрывных решений не ожидать гладкого порядка сходимости.

Допуски определяются масштабом задачи и числовым типом. Для баланса учитывать граничные потоки и источники. Ошибки измеряются на физических ячейках; аналитический эталон должен соответствовать представлению данных: значениям в центрах или средним по ячейкам.

Перед каждой реализацией выбирать проверки, подтверждающие её математический контракт. Не создавать тесты, которые лишь повторяют внутренние формулы реализации.

## Одномерный распад разрыва

Проверки будущей специализации описаны в [постановке задачи Римана](../docs/riemann-1d.md). Рабочая последовательная комбинация: идеальный газ, конечные объёмы, точный поток Годунова и явный Эйлер. Русанов остаётся планом.

- Равные состояния: постоянное решение и согласованность численного потока с физическим.
- Проекция разрыва: точное сохранение начальных интегралов при совпадении с гранью и при пересечении ячейки. Усредняются консервативные переменные.
- Задача Сода: независимый эталон, положения волн и ошибка средних консервативных величин на сгущающихся сетках до влияния границ.
- Изолированный контакт: одинаковые давление и скорость при разных плотностях; проверяются отсутствие паразитного скачка давления и измеримое размазывание контакта.
- Консервативность: баланс всех трёх величин с фактическими граничными потоками. В частности, не требовать постоянного полного импульса при разных давлениях на концах.
- Допустимость: положительные плотность и давление, конечные величины, корректный `gamma`, положение разрыва, диагностируемый отказ для неподдерживаемого вакуума.
- Время: пересчёт шага по текущим скоростям волн, включение граничных состояний, укорочение последнего шага и проверка результата до приёма состояния.
- Конфигурация: новая ветка принимает только свои поля; существующая волновая версия 1 сохраняет прежние результаты. Новый профиль принимает EulerConfig приложения; исходный волновой ConfigProcessor сохранён и по-прежнему отклоняет v2.

Основные сеточные проверки реализованы в finite-volume-test.cpp и cli-test.cmake/check-euler-output.cpp. В тесте Сода при t=0.2 L1-ошибка плотности снизилась с 0.0168737 (100 ячеек) до 0.0111308 (200). Эталонная плотность усредняется по ячейкам четырёхточечной квадратурой Гаусса с разбиением по положениям волн. Это проверка сеточного метода; независимые проверки самого локального решателя перечислены ниже.

## Точный решатель и поток Годунова

Подробная матрица проверок — в [спецификации](../docs/exact-riemann-solver.md). Отдельно проверяются локальное решение и его подключение к конечным объёмам. Обязательны чистый контакт, обе ударные и обе разрежения, попадание грани внутрь веера, стационарный удар, вакуумный порог, отказ по лимиту итераций и разные gamma. Для шага учитываются скорости найденных волн.

Проверка самого точного решателя требует независимого эталона; сравнение с вызовом его же sample недостаточно. Средние по ячейкам сравниваются с усреднёнными консервативными величинами, а не с точечными значениями. Добавлены `riemann-toro-test.cpp` и `riemann-test.cpp`: табличные случаи Торо, преобразования переменных, чтение данных из State, правый след на скачках, отражение, условия скачка, инварианты и края вееров, звуковой переход, стационарный контакт/удар, перенос всех волн в одну сторону, близость к вакууму, разные gamma и масштабы, ошибочные входы и лимиты поиска. Метод Годунова проверяется в finite-volume-test.cpp и пяти сквозных CLI-тестах. Сквозные тесты пишут только в cli-test-results дерева сборки. Пользовательские каталоги результатов для них не используются.

## Скрипт графиков

Отдельно от CTest, при установленных NumPy и Matplotlib:

```sh
python3 -m unittest discover -s tests -p test_plot_toro.py -v
```

Девять проверок покрывают текущий формат, переставленные строки, восстановление примитивных полей, сокращённый набор output.fields, одну ячейку и один момент времени, неравномерные времена, повреждённые слои, недопустимые состояния и отказ CLI до создания рисунков при status=failed. Тестовые файлы создаются во временном каталоге. Реальные пять расчётов также проверены запуском plot_toro.py; PDF содержит 15 страниц.
