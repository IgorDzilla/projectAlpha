# Как проверить программу

`solver-cli` теперь отбирает точное решение одного разрыва без временного цикла.
Проверки `finite-volume` и `solver` относятся к сохранённым сеточным классам,
которые пользовательский CLI не вызывает.

Все команды — из **project Alpha**.

## Проверки C++

```sh
cmake -S numerical-solver -B build-tests -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build-tests
ctest --test-dir build-tests --output-on-failure
```

Если всё хорошо, в конце будет `100% tests passed`.

Сейчас есть 11 проверок:

| Название | Что проверяет |
| --- | --- |
| `core` | Сетку и хранение значений |
| `solver` | Шаги времени, сохранение слоёв и остановку при ошибке |
| `riemann` | Пять точных задач Торо, баланс на ударных волнах, инварианты разрежения, контакт, вакуум, сходимость по допуску и данные для графиков |
| `finite-volume` | Начальные данные, баланс потоков и уменьшение ошибки при более мелкой сетке |
| `euler-config` | Чтение газового TOML, ошибки параметров и запись CSV |
| `cli-toro-1` … `cli-toro-5` | Прямой точный профиль каждого TOML и сверку его точек с `sample()` |
| `config-reader` | Твой utils: волновой TOML v1 и формулы через ExprTk |

Начальные условия Торо берутся из существующих `configs/toro_*.toml`. В C++ хранятся только опубликованные эталоны и допуски. Маленькие искусственные примеры проверяют отдельные свойства, например неизменность постоянного состояния или отказ при отрицательной плотности.

В `riemann-test.cpp` на каждом решении Торо проверяются условия Ранкина — Гюгонио для массы, импульса и энергии, рост энтропии на ударе, изэнтропичность и инварианты в веере, непрерывность давления и скорости на контакте. Отдельные примеры для γ=1.4 и 5/3 проверяют постоянное состояние, поток через неподвижный контакт, положительное решение перед порогом вакуума и обнаружение вакуума на пороге и выше него.

Проверка только пункта 1.3:

```sh
ctest --test-dir build-tests -R '^riemann$' --output-on-failure
```

Результат — `build-tests/toro-results/toro_1` … `toro_5`. В каждой папке:
`errors.csv`, `summary.csv`, `profile.csv`, `density_xt.csv`, `wave_curves.csv` и копия TOML.
В `summary.csv` есть звёздные состояния, GUESSP, начальное давление, число итераций и скорости волн.

Допуск сравнения: `atol + 2e-6 * |эталон|`. Обычно `atol` равен половине последнего
разряда таблицы Торо. Для скорости в тесте 5 `atol=5e-5`: округлённые начальные данные
дают `u*=8.6897744116`, в таблице — `8.68975`. Для нулевой скорости в тесте 2
используется абсолютный допуск `1e-8`, относительное отклонение не вычисляется.

Результаты тестов лежат внутри `build-tests`. Твои расчёты в `configs/results` они не трогают.

Запустить только проверку utils:

```sh
ctest --test-dir build-tests -R '^config-reader$' --output-on-failure
```

## Проверки графиков

Нужны NumPy и Matplotlib.

```sh
python3 -m unittest discover -s numerical-solver/tests -p test_plot_toro.py -v
```

Здесь 11 проверок. Они проверяют чтение обоих форматов CSV, восстановление полей,
построение графиков и таблиц, отказ при испорченных физических данных и непройденном
точном тесте. В конце должно быть `OK`.

Пересчитать пять точных тестов и построить весь вывод пунктов 1.3–1.4 одной командой:

```sh
cmake --build build-tests --target toro-plots
```

В `build-tests/toro-results/plots` появятся `toro_report.pdf` (таблицы и 15 рисунков),
`REPORT.md`, сводный CSV отклонений и PNG/PDF каждого рисунка. Python с NumPy и
Matplotlib выбирается CMake; при необходимости укажи `-DPython3_EXECUTABLE=/путь/к/python`
во время настройки сборки.

Если используешь окружение `.venv`, вместо `python3` укажи `.venv/bin/python`.
